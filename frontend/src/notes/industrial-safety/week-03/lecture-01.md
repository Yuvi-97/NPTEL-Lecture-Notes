# Week 3 – Lecture 1: FAULT TREE ANALYSIS (FTA)- Construction

## 1. Key Concepts
- **Fault Tree Analysis (FTA):** A top-down, deductive, graphical logic modeling technique designed to analyze the probability and causal combinations of lower-level component failures and human errors that lead to a specific catastrophic system-level **Top Event**.
  - *Origin & History:* Conceived in 1961 by **H.A. Watson** at Bell Telephone Laboratories for the US Air Force Minuteman Intercontinental Ballistic Missile launch control system; subsequently standardized by the US Nuclear Regulatory Commission (NUREG-0492).
  - *Deductive Nature:* Proceeds from the general disaster backward to the specific root causes: *"How could the Top Event occur? What combinations of events are necessary and sufficient?"*
- **The Top Event:** The ultimate undesired system failure or catastrophe selected as the apex of the fault tree (e.g., *Pressure vessel explosive rupture*, *Loss of aircraft flight control*, *Bhopal toxic gas release*).
- **Intermediate Events:** System-state fault events generated by the combination of lower-level inputs through logic gates.
- **Basic Events:** The terminal, initiating root causes at the bottom of the tree (component hardware failures, software bugs, human errors) whose failure probabilities are independently measurable.

## 2. Important Points

### Standard Fault Tree Graphical Symbols

#### 1. Event Symbols
- **Rectangle:** Represents the **Top Event** or an **Intermediate Event** resulting from the logical combination of input events through a logic gate.
- **Circle:** Represents a **Basic Event**—an independent, primary component failure requiring no further causal decomposition (e.g., pump bearing failure, relay contact welding).
- **Diamond:** Represents an **Undeveloped Event**—an event that is not further decomposed either due to lack of information or lack of safety significance.
- **Ellipse (Conditioning Event):** Applied to an Inhibit gate to denote a specific physical or operational condition that must be present for the logic gate to pass an output.
- **House Symbol:** Represents an **External / Normal Event** that is expected to occur or be present under standard operational conditions (e.g., plant operating in phase switch mode).

#### 2. Logic Gate Symbols
- **AND Gate:**
  - *Logic Function:* The output event occurs if and only if **all input events occur simultaneously**.
  - *Boolean Form:* $Y = X_1 \cap X_2 \cap \dots \cap X_n \quad (Y = X_1 \cdot X_2 \dots X_n)$
- **OR Gate:**
  - *Logic Function:* The output event occurs if **at least one of the input events occurs**.
  - *Boolean Form:* $Y = X_1 \cup X_2 \cup \dots \cup X_n \quad (Y = X_1 + X_2 + \dots + X_n)$
- **Inhibit Gate:**
  - *Logic Function:* The output event occurs if the input event occurs **AND** an attached conditioning event (ellipse) is satisfied.
- **Priority AND Gate:**
  - *Logic Function:* The output event occurs if all input events occur in a **specific chronological sequence** (usually left-to-right).
- **Exclusive OR (XOR) Gate:**
  - *Logic Function:* The output event occurs if one input event occurs, but **not if both occur simultaneously**.

#### 3. Transfer Symbols
- **Transfer-In (Triangle with line from apex):** Indicates that the logic tree branch is continued from another sheet.
- **Transfer-Out (Triangle with line into side):** Indicates that the branch attaches to a matching Transfer-In symbol elsewhere.

### Step-by-Step Construction Procedure for a Fault Tree
Building an analytically sound fault tree follows five rigorous steps:
1. **Define the Top Event unambiguously:** Must clearly specify the system boundary, operational phase, and specific failure mode (e.g., *"Storage Tank T-101 explodes due to overpressure during normal filling"*).
2. **Understand System Architecture & P&ID:** Establish complete knowledge of electrical wiring, piping, instrumentation, and control interlocks.
3. **Determine Immediate, Necessary, and Sufficient Causes:** At each level, identify only the immediate preceding causes without jumping directly to basic root failures.
4. **Select Appropriate Logic Gates:** Use an **AND gate** when all inputs must co-exist (e.g., demand occurs AND protection fails); use an **OR gate** when any single failure suffices.
5. **Decompose Downward to Basic Events:** Continue developing intermediate gates until all branches terminate in basic events (circles) or undeveloped events (diamonds).

## 3. Differences / Examples

### AND Gate vs. OR Gate System Reliability Implications
| Feature | AND Gate Logic | OR Gate Logic |
| :--- | :--- | :--- |
| **System Architectural Meaning** | Represents **parallel redundancy** / multi-barrier defense | Represents a **series system** (single-point vulnerabilities) |
| **Boolean Operator** | Intersection ($\cap$ or $\cdot$) | Union ($\cup$ or $+$) |
| **Mathematical Impact** | Drastically **reduces** probability ($P = P_1 \times P_2$) | Drastically **increases** probability ($P \approx P_1 + P_2$) |
| **Safety Engineering Target** | Maximizing AND gates in safety-critical systems | Eliminating OR gates attached directly to the Top Event |

### Fault Tree Construction Example: Benchmark Pressure Tank System
- **Top Event:** Catastrophic rupture of pressure tank shell ($TE$).
- **Intermediate Level 1 (OR Gate):**
  - Tank ruptures under normal operating pressure due to material defect ($BE_1$).
  - Tank overpressurizes beyond maximum allowable burst rating ($IE_1$).
- **Intermediate Level 2 (Under $IE_1$ — AND Gate):**
  - Tank continues to be filled past cutoff threshold ($IE_2$) **AND** Pressure Safety Valve (PSV) fails to open ($BE_2$).
- **Intermediate Level 3 (Under $IE_2$ — OR Gate):**
  - Timer relay fails to open contact ($BE_3$) **OR** Pressure switch contacts weld shut ($BE_4$).

```
                      [Top Event: Tank Rupture]
                                 |
                             [OR Gate]
                           /           \
           [Material Defect (BE1)]    [Overpressure (IE1)]
                                               |
                                           [AND Gate]
                                         /            \
                       [Continuous Pumping (IE2)]    [PSV Fails (BE2)]
                                   |
                               [OR Gate]
                             /           \
                 [Timer Fails (BE3)]   [Pressure Switch Fails (BE4)]
```

## 4. Must Remember
- **Fault Tree Analysis (FTA)** is a **top-down, deductive** logic modeling tool developed by H.A. Watson in 1961 for aerospace and nuclear safety.
- The **Top Event** must be defined with extreme precision, stating the specific failure mode, operating state, and environmental context.
- **AND gates** represent parallel redundant protection where all inputs must fail simultaneously ($Y = X_1 \cap X_2$); they lower the probability of the output event.
- **OR gates** represent series vulnerabilities where any single input failure triggers the output ($Y = X_1 \cup X_2$); their presence near the Top Event signals dangerous single-point failure paths.
- Terminal tree symbols are strictly standardized: **Circles** represent Basic Events, **Diamonds** represent Undeveloped Events, and **Rectangles** represent Top and Intermediate Events.
- FTA construction must proceed level by level, identifying **immediate, necessary, and sufficient causes** rather than jumping prematurely to basic component failures.
